# `@libid/ceremony` test plan

This plan tests the `@libid/ceremony` package architecture in
[ARCHITECTURE.md](ARCHITECTURE.md) and its browser protocol in
[CCDP.md](CCDP.md), its prover subsystem in [PROVER.md](PROVER.md), and the
integrating-server contract in [SERVER.md](SERVER.md).
Normative proof and platform behavior come from the
[common ceremony rules](../../../specs/ceremony-common.md) and
[identity-platform ceremonies](../../../specs/platform-ceremonies.md).

Every row is one stable requirement and may require multiple positive and
negative cases. Tests **must cite its ID**. Existing IDs retain their names;
never renumber or reuse one.

A row belongs here only when it exercises `@libid/ceremony`, an emitted browser
asset, or a server/browser contract declared by the package. Consumer-owned Job
transitions, wallet preparation or confirmation, transaction submission, and
post-ceremony recovery belong to their respective consumer test plans.

| LIBID-PROVER-003 | X v1 emits its defined spans, notarizes token before identity, validates the bounded printable bearer, commits it with independent 16-byte blinders, reveals only the prescribed ranges, and proves `bearer-link`. | LIBID-PROVER-004 | GitHub v1 emits its defined spans and exact-validates the server token response, attestation correlation, request bindings, layout, live fields, and bearer opening before `/user`; failure discards it. | LIBID-PROVER-005 | The X and GitHub profiles point to the same immutable `bearer-link` circuit URL and resolve the same global notarization-client module/WASM pair and code-pinned prover toolchain. | LIBID-PROVER-006 | The selected notary release supplies pinned sibling `tlsn_wasm.js` and `tlsn_wasm_bg.wasm` files built from the notary repository's pinned TLSN revision, including `set_progress_callback`, with the worker bootstrap embedded in the module. | LIBID-PROVER-007 | Every successful run emits one `started` and one `completed` for every diagnostic span, including cache hits. | LIBID-PROVER-008 | Only X token, X identity, and GitHub identity call the internal notarization adapter. | LIBID-PROVER-009 | Before the notarization wrapper returns, every raw TLSNotary commitment and opening maps exactly once by direction, range, and value to the read-only decoding of the original signed attested-data bytes. | LIBID-PROVER-010 | The read-only decoder reproduces every field and the pinned digest of the upstream `libid-rs` fixture referenced by NOTARIZATION.md. | LIBID-PROVER-011 | Every platform/version progress catalog assigns a bounded package-owned display label to each code and nonnegative weights to leaf spans only. Parent weight is zero and leaf weights form one positive total. For every valid serial and parallel completion order, emitted progress equals `0.95 * completedWeight / totalWeight`, remains finite and monotonic in `[0, 1)`, does not advance on `started`, and never double-counts nested spans.
